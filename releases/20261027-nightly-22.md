# 시험판: Voxy 268MB 블록 아틀라스 중복 PBO 덤프 완전 스킵 최적화

Voxy와 Iris의 차원 이동 상호작용 및 바이트코드 분석을 바탕으로, 차원 전환 시 Voxy가 8192×8192(268MB) 텍스처 아틀라스를 불필요하게 GPU에서 다시 PBO로 덤프하며 유발하던 0.4초의 GPU 펜스 동기화 지연과 백그라운드 워커 스파이크를 완전히 제거하는 최적화를 적용했습니다.

<details><summary>수정 내용과 검증</summary>

- **Voxy 268MB 블록 텍스처 아틀라스 중복 덤프 스킵 (`VoxyAtlasReuseMixin`, `VoxyAtlasReuseState`)**:
  - 기존 동작:
    - Voxy는 차원 이동 시 기존 렌더 파이프라인을 종료하고 새로 생성하면서 `SoftwareModelTextureBakery.setupTexture()`를 실행.
    - 이때 `RenderResourceReuse`에서 268MB 버퍼를 재사용(`reused=true`)하여 메모리 할당은 피했으나, `ModelAtlasReadback.tryBegin()`을 무조건 다시 호출하여 268MB 전체를 GPU에서 PBO로 재전송하도록 요청함.
    - 마인크래프트에서 블록 텍스처 아틀라스(`textures/atlas/blocks.png`)는 리소스팩 재로드를 하지 않는 한 차원이 바뀌어도 100% 동일한 정적 텍스처임에도 불구하고, 매 차원 이동마다 268MB PCIe 전송 및 374~582ms의 GPU 펜스 대기(`readyElapsedMs`)가 발생함.
    - 이 대기 시간 동안 Voxy의 모델 베이킹이 멈췄다가 펜스가 풀리는 순간 10개의 워커 스레드가 한꺼번에 폭발적으로 깨어나 일시적 CPU/GPU 렉을 가중시킴.
  - 개선 내용:
    - `SoftwareModelTextureBakery._doSetupTexture` 실행 시 `buffer.reused() == true`이고 텍스처 ID가 동일한 경우, 268MB PBO 덤프(`tryBegin`)와 동기 읽기(`readSynchronously`)를 완전히 건너뛰고 0.001ms 만에 즉시 `installTexture()`로 직행하도록 최적화.
    - 리소스팩 리로드(F3+T)나 텍스처 ID 변경 시에는 자동으로 dirty 플래그를 감지하여 안전하게 정상 읽기 수행.
  - 효과:
    - 차원 이동 시 Voxy 아틀라스 준비 지연: **374~582ms ➔ 0ms (완전 제거)**.
    - 268MB PCIe 버스 대역폭 낭비 원천 차단.
    - 차원 전환 직후 Voxy 10개 워커 스레드의 지연 폭발 기동 스파이크 제거.

오프라인 네이티브 믹스인 변환(70개 시나리오) 및 Voxy 바이트코드 핑거프린트 핀 검증 완료.

</details>
