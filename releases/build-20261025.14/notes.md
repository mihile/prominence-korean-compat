접속과 차원 이동 때 반복되던 Iris 셰이더 전처리 결과를 디스크에 저장합니다. 게임 재시작 후에도 동일한 입력이면 재사용합니다. 통합 JAR 이름과 모드 버전 `1.0.0`은 유지합니다.

<details>
<summary>변경 내용</summary>

- include가 합쳐진 전체 소스, 순서와 값이 포함된 전체 환경 정의, native 구현 지문을 키로 사용합니다. 옵션·셰이더·차원 정의가 바뀌면 원래 전처리를 다시 실행합니다.
- 원래 Iris/JCPP의 경고·오류 수를 확인해 정상 결과만 저장합니다. 경고·오류·예외를 숨기지 않으며 시간/외부 파일에 의존할 수 있는 입력은 원래 처리로 돌아갑니다.
- 완료 캐시는 최대128MiB/1024개, 항목당2MiB입니다. 쓰기는 낮은 우선순위의 단일 백그라운드 작업으로 수행하고 대기 문자열은4MiB/16작업 이내로 제한합니다. 월드·파서·GPU 객체를 보관하지 않습니다.
- 최초 디렉터리 검증과 쓰기·정리 전 경계를 확인하며, 알 수 없는 파일은 지우지 않습니다. 손상되거나 읽을 수 없는 캐시는 원래 계산으로 돌아갑니다.
-100ms 이상 걸린 Iris pipeline 준비 시간과 누적 캐시 적중/원래 계산 횟수를 로그로 남깁니다. 기존 Euphoria 차원 전환 처리, Voxy와 모든 이전 호환 기능은 유지합니다.

`-Dprominence.shaderSourceDiskCache=false`로 이 연동만 끌 수 있습니다. 검수한 Iris1.7.6+mc1.20.1/JCPP1.4.14의47개 클래스 지문에 일치할 때만 활성화됩니다. 서버와 화질·거리·키·셰이더 옵션은 변경하지 않습니다.

</details>

<details>
<summary>검증과 실제 효과의 범위</summary>

기존 유효 JFR과 현재 기동 로그를 활용했습니다. build13의6개 메모리 모듈 활성화를 확인했으며 EMI는 최근 로그에서18,025ms였습니다. 렌더 스레드의 ShaderPack/JCPP 처리와 GPU 컴파일·EMI·Voxy 비용을 구분했습니다.

실제 native Mixin 변환2대상18메서드와 Euphoria pipeline hook 보존을 확인했습니다. 설치된 셰이더의 include를 원래 Iris로 합친 소스를 포함해151개 native 전처리/재사용/경고·오류/새 캐시 인스턴스 검사를 통과했습니다. 별도 데이터·용량·큐·47개 지문 검사와 기존 회귀 검사도 수행했습니다. 이전385개 클래스, updater helper와 빌드 외 기존 엔트리는 바이트 그대로입니다.

오프라인 CPU 검사에서 반복 전처리의 비용 감소를 확인했습니다. 이 수치를 실게임 전체 접속 시간이나 FPS 개선율로 사용하지 않습니다. 첫 캐시를 만드는 실행·처음 보는 입력은 원래 계산이 필요하며 GPU 컴파일과 EMI 초기화 비용은 남아 있습니다. 실제 새 연동 활성화와 첫 접속/차원 이동 효과는 다음 한 번의 통합 실행 검수 대상입니다. 게임/월드/OpenGL은 도구가 실행하지 않았습니다.

</details>
