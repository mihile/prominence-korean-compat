# EMI first-join creative groups

Client build2026102704 targets the item-group refresh observed in the build2703 first-join capture. EMI logged 1,874ms on the client thread inside a 5.36-second frame interval, and JFR sampled AE2 facade generation through block geometry/state checks. The interval also contains loading and other initialization; it is not all attributable to AE2 or EMI.

AE2 15.4.11 scans every other creative tab and calls `FacadeItem.createFacadeForItem(stack, false)` for every entry. Multiple tabs can include the same block. Its pinned native implementation rejects empty stacks and any NBT, accepts block items, consults default block state/config/tags, and creates a facade whose only NBT is that item's registry ID. Minecraft's native linked item-stack set already collapses identical facade results.

During one synchronous facade-tab build, the patch remembers the identity of each plain block item after its first completed native evaluation. Later duplicate plain inputs return empty to the caller, because their identical result was already inserted into the native set. It preserves the first insertion and its order. Empty, NBT-bearing, custom stack, custom block-item and custom facade-factory types use the original method. Test-only calls also use the original method. The native loop, Throwable catch, output callback, thread and item-tab order remain intact.

The identity set belongs to a nested/thread-local try-with-resources scope and is cleared on exit, including exceptions. No item stacks, recipes, worlds, resource models or future rebuild results are retained. A new rebuild evaluates all distinct candidates again, so updated tags/configuration are observed. It neither hides the AE2 tab nor changes EMI's configured index source. It does not move game registry/model work to a background thread.

Independent `facades` and `creativeTiming` guards require exact installed versions and class SHA256 pins. The facade guard additionally pins native Minecraft ItemStack, BlockItem, ItemStackSet and its equality strategy. Existing `terrain`, `keys`, and `itemIds` guards remain separate. Diagnostic opt-outs are `-Dprominence.emiHome.facades=false` and `-Dprominence.emiHome.creativeTiming=false`.

One log line per facade build records eligible candidate count, repeated count and elapsed milliseconds. The original EMI group callback additionally reports groups taking at least 20ms, using their display names. This is local logging, without a HUD overlay or per-item logging.

`tools/verify_creative_native.py` applies actual Mixin/MixinExtras transformations to the installed AE2 and EMI classes and runs ASM verification with the previous EMI index wrapper. A headless fixture executes the native AE2 iteration/catch/output method and the native Minecraft linked item-stack set/equality strategy, with small item/block/factory stand-ins and unused client bootstrap methods omitted. Its repeated-input case has identical output/order with 2,010 original factory calls versus 10 patched calls. NBT/custom types, identity-distinct same-name items, updated configuration, exception cleanup, separate rebuilds, nested scopes and separate threads are checked. This proves fixture behavior and operation reduction, not a game benchmark or actual block-model execution.

Previous cumulative classes, update helper/key, and updater/other-module regression checks must be preserved. Real first-join EMI wall time, frame tails and memory impact remain unmeasured at publication. Validate them using JFR, PresentMon, GPU sampling and low-frequency Windows memory at the same house before proceeding to another optimization. Do not heap-dump or force GC during that recording. Existing MAT evidence is sufficient for the queued old-world-reference investigation.
