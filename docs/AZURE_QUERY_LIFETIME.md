# AzureLib query owner lifetime

Client build2026102705 follows the first-join measurement of build2704. That measurement verified 876 repeated AE2 plain-block checks were skipped among 16,296 eligible candidates (about 5.4%); it did not establish lower total EMI wall time (19.13s before versus 20.40s after, with less system RAM available). The short repeated-input fixture from build2704 was not representative of the real duplicate ratio. The first-join frame tail remains unresolved.

The next change uses the existing post-transition heap/MAT evidence, not another forced collection during a performance recording. MAT identified a strong path from AzureLib's static `MolangParser.VARIABLES` through a `LazyVariable`, `MolangParser$1`, and a native `GeoModel` lambda to an obsolete client world. Native bytecode confirms that actor-count and moon-phase method references capture the then-current world. Other core query lambdas capture entities. A memoized numeric result does not release those captured objects.

The existing END_CLIENT_TICK cleanup now includes an independent, exact-pinned `azureQueries` module. It runs only when the weak world/player transition detector reports a change. It inspects eleven fixed world/entity core queries. A provider is eligible only if the variable has the exact native class, its current supplier is the exact native memoizer, the memoizer delegates to a hidden lambda nested in the native `GeoModel`, and that lambda directly captures a client world/entity belonging to a different world. Current-world owners, server-world owners, time-only queries, direct/nonmemoized providers, unknown shapes and providers originating in other classes remain unchanged.

The patch replaces only that variable's obsolete value provider with a shared zero supplier. It preserves the `LazyVariable` itself because parsed animation expressions may keep references to it. Removing a map entry alone would leave those parsed references holding the old provider. The original animation setup repopulates the same variable on the next native render, using the same native memoization and numerical operations. Identity checks protect a replacement installed during inspection. No global map clear, per-frame scan, new render mixin, weak-supplier allocation on every frame, forced game GC or cache-capacity change is added.

`WorldCacheGuard` pins AzureLib3.0.27's GeoModel, parser, memoizer, LazyVariable and MolangQueries bytecode plus Minecraft1.20.1. Missing/changed classes or `-Dprominence.worldCacheCleanup.azureQueries=false` disable this optional cleanup. Startup logs `Client AzureLib stale query cleanup: enabled`; a transition that releases providers logs only the count. A field-shape failure disables the module and preserves native behavior.

`AzureQueryPrunerTests` executes the real AzureLib parser/memoizer/LazyVariable implementation with ordinary owner stand-ins, without a game or world. It reproduces retention even after numeric evaluation, keeps the parsed variable alive while proving the obsolete owner becomes collectible after cleanup, verifies active/server/custom/direct/replaced providers and disconnect/repopulation behavior, checks exact bytecode lambda captures, and rejects modified/missing/version-drift pins. Any GC in these tests is in an isolated test JVM after the user's recording, never in the game. Existing regression checks and cumulative class/helper/key preservation must also pass.

This repairs the observed AzureLib ownership path; it does not establish a particular whole-game memory saving or first-join frame improvement. The separate EMI Trades synthetic-villager ownership path remains unresolved. No server code is required. Public source/feed publication and live installation/behavior validation are recorded separately; no running client or server is directly replaced.
