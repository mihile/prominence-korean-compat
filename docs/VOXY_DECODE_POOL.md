# Scoped LOD bulk decode index reuse

The 21:06 capture ran client build2026102710 with `remoteIngestScratch=enabled`. Explicit VoxelizedSection.createEmpty allocation samples on the ingest stack fell from roughly 175 MiB to 8 MiB, with different uncontrolled workloads; this is an allocation-sample estimate, not a retained-heap or frame-time saving. The new capture attributed about 3581 MiB sampled allocation to `short[]` in bulk decoding. EMI remained about 19.96 s. The measured first-join display stream contains a 10.5 s CPUStart gap inconsistent with the reported frame time and cannot establish a single frame duration.

For the installed 1.20.1 VoxyServer port.3 decoder only, within the already guarded ingest-task scope, decode wire data with the same bounds, order and packing as the native reader. Borrow only full-size 32768-entry `short[]` arrays. Every array is fully overwritten by decoding, remains exclusively owned until the entire task ends, and is then returned to a synchronized pool capped at 32 arrays (2 MiB); excess arrays are discarded. Different lengths and calls outside the guarded task use native allocation. Failed/truncated payloads return any borrowed arrays in the task finally scope. Nested and concurrent tasks cannot borrow a still-owned array. The protocol, server, packet ACK, world insertion, hash synchronization and all other operations stay unchanged. Decoder and payload class hashes are pinned; the previous task guard must also be active. Disable the decoder with `-Dprominence.emiHome.remoteIngestDecode=false`.

Tests compare the exact native VoxyServer encoder and decoder to the replacement over randomized wire packets, batches, index widths and truncated input, and check alias safety, exception handling, concurrency and bounded reuse. The actual installed decoder is Mixin transformed and ASM verified. These are offline tests, not world/GL gameplay or a performance benchmark. Current runtime FPS, actual LOD correctness and heap effect require normal game verification. The bounded pool retains up to 2 MiB intentionally; it is not a persistent per-world or unbounded cache.

MAT for the same capture reports WorldEngine retained 538702792 bytes, ModelFactory 344535128 bytes, and KnotClassLoader 689199648 bytes. These are separate dominators at snapshot time, not necessarily waste; do not add nested retained values or equate allocations with live RAM. The snapshot contains one client world in the custom report; this alone is not a leak finding.
