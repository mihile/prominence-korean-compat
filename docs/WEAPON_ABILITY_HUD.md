# 무기 특수기와 상호작용 우선순위

우클릭으로 상자·NPC·문 등을 사용했다면 그 입력을 무기 발동에 다시 쓰지 않습니다. 메뉴를 닫을 때 우클릭을 계속 누르고 있어도 특수기를 발동하지 않으며, 버튼을 놓았다가 다시 누르면 정상적으로 사용합니다. 컨테이너를 가리킨 기본 사용은 블록의 화면 제공자를 확인합니다. 웅크리기로 블록 사용을 우회하는 동작과, 사용 키와 다른 별도 능력 키는 유지합니다. MISS 광선 결과를 실제 블록으로 취급하지 않습니다.

기존 Spell Engine 주문 HUD에 무기 아이콘과 실제 연결 키를 표시합니다. 주문 슬롯이나 입력 처리를 위한 가짜 주문을 등록하지 않고 **표시 모델만** 추가합니다. 기존에 같은 아이템을 나타내던 항목은 중복하지 않으며 보조 손 사용의 기존 수정키도 보존합니다.

build2026102604부터 무기 능력 아이콘은 맨 왼쪽에 배치합니다. 이름·상태·남은 초를 따로 적던 설명 줄은 표시하지 않습니다. 아이콘의 실제 사용 키와 원래 쿨타임 음영은 유지하며 주문 아이콘의 상대 순서나 실제 단축키/사용 처리는 바꾸지 않습니다.

- 쿨타임이 있으면 서버가 원래 동기화하는 아이템 쿨타임의 진행 음영을 표시합니다. 새 타이머·쿨타임 배율·서버 패킷은 없습니다.
- 리비아탄 투척은 자신이 던진 무기가 추적되고 주 손이 비어 있으면 귀환 대기 상태의 아이콘을 유지합니다. 다른 아이템을 들거나 투사체가 추적 범위를 벗어나면 이 임시 표시를 숨깁니다.
- 각성이 필요한 고유 무기는 사용할 수 없는 상태의 음영을 유지합니다. 진행 제한이나 피해·마나·쿨타임 조건을 완화하지 않습니다.
- Simply Swords의 UniqueWeaponActiveAbility 공통 구현50개, 활성 룬 능력과 창 투척을 지원합니다. Soulslike Weaponry의 해당 무기와 Mine Cells의 Flint/Hattori/Tentacle, Archon의 SpellWeapon/TerraneanAxe, Bumblezone의 StingerSpear도 포함합니다. 모드 폴더의 검·도끼·삼지창 사용 오버라이드 후보107개/선언83그룹을 정적으로 대조했고, Tech Reborn의 전원 전환2개는 스킬 표시에서 제외했습니다. 일반 활 당기기·바닐라 도구를 모두 특수기로 표시하지 않습니다. 룬 창은 실제 기본 투척 키를, 별도 키가 있는 능력은 현재 설정 키를 사용합니다.

<summary>원인과 검증 범위</summary>

현재 Simply Swords의 기본 능력 호출은 아이템 사용 맥락을 받지만 컨테이너 상호작용을 별도로 구분하지 않습니다. 별도 능력 키도 사용 키와 같은 물리 버튼이면 직접 눌림 상태를 읽어 서버 패킷을 보낼 수 있습니다. Minecraft의 사용 키 유지/화면 전환 및 블록 사용 실패 후 아이템 사용 경로에서 이 입력을 다시 쓰지 않도록, 아이템 사용 패킷 전송 전과 공유 능력 키 경로를 보호했습니다. 제보 순간의 입력 추적 로그를 수집한 것은 아니므로 당시의 단일 호출 경로를 확정했다고 주장하지 않습니다.

Spell Engine의 원래 표시 모델은 SpellCooldownManager를 읽습니다. Simply Swords의 플레이어 능력은 원래 ItemCooldownManager를 사용하므로 주문 HUD에 자동으로 나타나지 않습니다. 리비아탄 기본 투척은 무기 스택을 줄인 다음1틱 설정을 호출하며, 빈 스택에는 그 설정도 적용되지 않습니다. 이번 표시는 이를 긴 쿨타임으로 바꾸지 않습니다. 투척 아이템은 LivyatanEntity의 서버 전용 필드 getter 대신 동기화된 ITEM_STACK 추적 데이터를 읽습니다. 투사체는 약한 참조1개만 유지하고 접속 종료·로드 해제 때 정리합니다. 월드 전체 순회나 새 네트워크 조회를 하지 않습니다.

Minecraft1.20.1 / Simply Swords1.70.2-1.20.1 / Spell Engine0.15.12+1.20.1 / MixinExtras0.5.4와16개 핵심 native 클래스 지문을 확인합니다. 추가 제공자는 버전과45개 클래스 지문을 별도로 확인하며, 변경된 제공자의 표시만 제외합니다. 실제 native6대상116메서드 변환/ASM에서 기존 Spell Engine 입력 믹신과 HUD 장비 조회 scope를 함께 적용했습니다. 아이템 사용 보호가 원래 패킷 경로보다 앞에 위치하는지 확인했습니다. 원래 cooldown 메서드는 보존하며 실제 변환한 manager/entry로 감소·진행률·만료4가지를 실행 검증했습니다.211개 입력 의도 검사와 기존 회귀 검사도 통과했습니다. 게임·월드·OpenGL은 도구가 실행하지 않았습니다. 실제 상자/무기/HUD 조작은 적용 후 사용자 실행 검수 대상입니다.

초기 구현에서는 기존423클래스와 업데이트 helper를 보존했습니다. 이번 HUD 배치 수정도 클라이언트 전용이며 서버 JAR·서버 설정·서버 ZIP은 갱신하지 않습니다. 배낭 재단조 서버 배포는 별도 기능의 최신 공개 지침을 따릅니다.
