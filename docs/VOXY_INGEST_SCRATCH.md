# Remote LOD ingest temporary section reuse

The 2026-10-27 20:03 JFR capture showed repeated allocation on VoxyServer Remote Ingest. Explicit sampled stacks attributed about 175 MiB estimated allocation to VoxelizedSection.createEmpty; larger `long[]` samples and `short[]` decode samples have other stacks and are not assumed to be eliminated. Allocation samples are estimates, not retained heap or a measured improvement. First-join stutter is not proven to have a single cause.

The installed VoxyServer internal version is 1.2.4+1.20.1-port.3 and Voxy is 0.2.20-beta+1.20.1-port.9, despite different filenames. Exact native hashes for ingest task, ingest service, section, mip and world updater are checked before either mixin activates. Different hashes or opt-out `-Dprominence.emiHome.remoteIngestScratch=false` leave both original paths enabled.

Each ingest task receives a private, lazy scratch VoxelizedSection. The first creation delegates to the original operation. Subsequent subdivisions clear all levels and counts before use; native code sets position, fully populates level zero, computes mips, then calls synchronous WorldUpdater.insertUpdate before reusing it. A nested task receives a separate scratch, and the thread-local scope and section are removed on all exits. No queue, packet, acknowledgement, hash, server data, upload or WorldUpdater logic is changed. Source and installed bytecode must stay pinned together; do not reuse this assumption after a Voxy update without revalidation.

Tests cover the actual installed ingest Mixin transforms and native section reset, nested scopes, concurrent scopes, exception cleanup and 960 randomized subdivision comparisons to fresh buffers. These fixtures do not start a game or render a world and do not establish runtime performance or full mip/world equivalence. Actual client play, LOD correctness and comparison capture remain necessary. The most heavily sampled allocation stacks at lines 196/221 and decoded short arrays are separate candidates, not removed by this change.
