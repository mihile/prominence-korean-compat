# Loot probability fallback

The aberration heart's installed Eldritch End table has one guaranteed-count item behind an entry-level 1% condition, followed by a native Looting quantity function. The old catalog rejected every entry-level condition, so EMI showed an unavailable probability even though it retained the 1% condition text. A single entry with exactly one draw can safely retain its conditional probability; the live EMI chance is then applied exactly once. This describes the native baseline. Client2026110410 / server2026110408 additionally correct the previously omitted occurrence scaling for quantity-only Looting functions; authoritative metadata then supersedes this baseline and displays the adjusted chance. See RARE_REWARD_SCALING.md.

The catalog now also computes nonempty-output probability for supported zero-producing count distributions, respecting replacement/addition order. It reads entry, pool and table functions. Conditioned sibling entries, repeated entry-condition draws, context-dependent functions and duplicate source pools remain conservative. They cannot be inferred from EMI's expected selection count. Ambiguous/unsafe rows previously accepted are removed rather than guessed.

Fallback tooltips always show a probability expression. For available base-table models they also show draw providers, selection weights and the quantity expression, including current Looting and native rounding/limits. Shift adds bonus draws and processing identifiers. Unknown server callbacks retain live predicates and explicitly state that custom roll metadata is needed. Base-table explanations are labeled as such, not represented as authoritative descriptions of arbitrary server datapack changes. Exact server-synchronized reward metadata remains preferred. Cycling slots with different structures are not assigned the first member's formula.

The generator scans installed mod/Minecraft tables; detailed JSON is retained only for rows without an exact model to avoid duplicating every probability entry in the client cache. The display-only correction does not change drops, reward scaling, world data, configs or other mods. It ships through the signed client nightly update feed.

Verification includes nine independent generator regressions, installed heart data, native Text/tooltip calculation (1% with and without Looting), fallback quantity/English formulas, stale expected-value rejection, native EMI Mixin transforms and cumulative updater/ASM checks. No game, server, world or OpenGL is started. Actual screen layout remains to verify in game.
