# EMI 초기화와 집 첫 접속의 동시 부하

client build2026102703. 기존 음악/메뉴/분류표 보완 이후, EMI 및 접속 중 청크 제출 경로를 직접 보완한다.

## 측정 근거

같은 집 첫 접속 기록에서 EMI 초기화19.42초 중 플러그인 등록7.62초, 검색 생성4.76초, 레시피 인덱스2.83초였다. 동기 인덱스가 약965만 번, 후속 정렬 인덱스가 약964만 번 키 문자열을 요청했다. 각 인덱스의 서로 다른 키는 약1만 개였고 JFR에는 이 임시 키 캐시의 ThreadLocal/HashMap 조회가 반복된다. 이미 있는 키 캐시는 변환 문자열의 생성을 줄였지만, 모든 요청의 임시 캐시 조회 자체는 여전히 수행했다.

일반 렌더 스레드에는 Custom Item Attributes의 아이템ID 재파싱이 기록됐다. EMI 작업 범위 밖에서는 이전 EMI용 임시 캐시가 적용되지 않는다. 이때 hotbar/ItemBorders의 툴팁·속성 조회에서도 같은 설정ID를 계속 파싱한다. 할당 표본을 실제 지속 점유량으로 해석하지 않는다.

접속 11:32:40–11:33:08 구간의 JFR CPU 표본상 시스템 평균 사용률은87.6%, 클라이언트 JVM 평균은66.3%였다. CPU는16논리 코어, Sodium의 작업자10개와 Voxy의 작업자11개가 서버/EMI/렌더 작업과 겹친다. 이 자료는 CPU 경합을 줄일 후보를 뒷받침하지만 개별 긴 프레임의 원인이나 개선량을 확정하지 않는다.

## 변경

1. **EMI 전리품 키:** 기본 `getId()`와 final 불변 Identifier를 사용하는 `EmiStackWithTitle`은 원본 getKey의 문자열 결과를 해당 객체에 보관한다. 기존 키 캐시와 변환을 최초 한 번 거친다. getId를 오버라이드한 하위 클래스, 알 수 없는 ID형, null/예외는 원래 경로를 사용한다. 이름·한국어 검색·레시피 비교 기준·검색 결과는 바꾸지 않는다. 세계·아이템스택·툴팁을 전역 보관하지 않는다. 캐시 필드의 수명은 원래 EMI 스택과 같다.
2. **일반 플레이의 속성ID:** `ItemProperty.getItem()`에서 동일 String 참조를 다시 받으면 성공한 Identifier 파싱만 재사용한다. 등록된 Item을 찾는 레지스트리 조회는 매번 수행한다. 설정 문자열을 교체하면 다시 파싱하고, 잘못된 ID의 예외는 저장하지 않는다. 속성 결과·NBT·슬롯·UUID·피해량은 캐시하거나 변경하지 않는다.
3. **접속 중 CPU 경합:** EMI ReloadWorker가 실행 중인 동안에만 Sodium의 일반 비동기 작업 예산을 조절한다. 이미 실행 중/대기 중인 작업을 모두 세고, 네이티브 작업자가4개 이상이면 절반 정도까지만 일반 선행 작업을 넣는다. 원래 예산을 늘리지 않고, 작업 자체를 삭제/취소하거나 스레드 수·우선순위를 변경하지 않는다. `IMPORTANT_REBUILD`와 네이티브 동기 갱신 수집기는 이 예산을 사용하지 않아 그대로 유지된다. EMI의 finally 이후 원래 예산으로 돌아가며 실패·중첩·동시 scope도 처리한다. 초기화 중 일반 지형 표시가 조금 늦어질 수 있으며 프레임 정체를 줄이기 위한 제한이다. EMI가 끝난 뒤 집 주변의 지속 렌더링 처리량은 제한하지 않는다.

셰이더 품질·시야 거리·개인 설정은 변경하지 않는다. Iris 파이프라인 전체 재사용은 별도 미해결 검토 항목이다. 이 수정으로 집 주변의 모든 렌더링 비용이 사라진다고 주장하지 않는다.

## 가드와 진단

`prominence-emi-home-pins.json`은 EMI1.1.24, EMI Loot0.7.9, Custom Item Attributes2.0.0, Sodium0.5.13의 실제 클래스 지문을 모듈별로 확인한다. Minecraft1.20.1/MixinExtras0.5.4가 필요하다. 지문/모드가 달라지면 해당 모듈을 비활성화한다. 진단 opt-out은 `-Dprominence.emiHome.keys=false`, `-Dprominence.emiHome.itemIds=false`, `-Dprominence.emiHome.terrain=false`다. 실제 JVM 옵션은 자동 수정하지 않는다.

## 검증

`tools/verify_emi_home_native.py`:

- 실제4클래스의 Mixin/MixinExtras 변환과58메서드 ASM 검사. 이전 EMI 키/리로드 wrapper를 함께 적용한다.
- 실제 전리품 키 원본 내부 경로와 수정 경로를 비교한다. 기존 임시 문자열 캐시를 켠 상태에서100만 번의 이전 scope조회가 수정 후1회로 줄며, ID문자열 생성은 양쪽 모두1회다. 동적 getId 하위 클래스는 바뀐 ID를 즉시 반환한다. 상위 EMI 클래스는 게임/GL 초기화를 피하기 위한 테스트 facade이며 게임 인덱스 전체를 생성한 실험은 아니다.
- 실제 ItemProperty 생성자/getItem 변환을 실행하되 레지스트리 접근만 테스트 probe로 교체한다. 동일 ID파싱을 재사용하고1004번의 조회는 매번 레지스트리 경로를 통과하며 설정 교체도 반영한다. Gson의 생성자 우회 역직렬화와 런타임 캐시의 JSON 직렬화 제외도 확인한다.
- 실제 Sodium getSchedulingBudget을 생성자 없이 만든 데이터 fixture에서 실행해 제한과 원복을 확인한다. 실제 작업자·게임·월드를 시작하지 않는다. helper25061검사로 모든 작은 pool/queue/busy 조합, 중첩·동시·오류 scope복구를 검사한다.
- 파싱100005회 동작 검사 및15가지 지문 시나리오를 확인한다. 이전 전체468클래스와 업데이트 helper/공개키 보존을 별도로 확인한다.

실제 집 첫 접속의 FPS/프레임 개선량과 EMI 전체 초기화 시간은 배포 후 미측정 상태다. 다음 검수는 이번 빌드 한 번의 재시작으로 같은 집에 접속해 프레임/JFR/GPU를 함께 비교한다. 원본 자료는 로컬에만 보관한다.
